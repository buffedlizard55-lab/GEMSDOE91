No method below has been implemented or tested in this review.** Their ordering is a qualitative judgment about information gained per cost, not a predicted leaderboard score. The requested assigned single-method paragraph was not present in the supplied context; none of these proposals is a coordinator assignment. Do not start one until that lane is established and a preflight permits it. ## Preregistered requirements for any later test

1. Freeze one authenticated assigned lane, exact input hashes, hypothesis, transforms, cost limit, dot budget, 100 m grid and the full available registry *before* observing holdout results. A capacity preflight is necessary but not sufficient. Check both pre-placement surface rank and final-dot rank/overlap; stop at the first duplicate. The current shared code conservatively uses absolute Spearman correlation for the 0.90 threshold; the user's text says `rho > 0.90` without explicitly specifying absolute value, so record that conservative interpretation rather than rewriting historical results.
2. Split **whole fault segments/components with spatial buffers**. In each fold, compute fault-derived features and any catalogue exclusion from **visible faults only**. Static geophysical transforms must be label-blind; fit data-dependent normalizers, units/strata, selection and any model using the training fold only. Mask the visible catalogue **pixel-exactly** during scoring, not a hidden-fault catalogue or an arbitrary collar. A spacing/collar used for candidate generation is a separately recorded design choice, not the scoring mask.
3. Use the shared `vendor/gems57/evaluate_holdout.py` / instrument `gems57-pooled-hide-v2`: pooled DTI (α 0.2, β 0.8, 300 m triangular kernel), paired same-fold incumbent, actual withheld-positive counts, and 95% spatial-block confidence interval. These are catalogue-recovery holdout values, not leaderboard predictions. Do not compare unpaired or differently instrumented numbers as a gain.
4. Canary each input, engineered feature and selection surface independently on each fold. Symmetric feature-only AUC >0.90 is leakage until disproved; a lower value does **not** prove absence of leakage. Record the nonfault mimic, no-NaN/range/CRS/shape/transform re-read, surface and dot comparisons against every registered file, byte hashes, filename, ≤140-character note and negative/promotion verdict.
5. Even a candidate that passes the checks remains only eligible for the separate selector; do not consume a live submission slot automatically. Do not recommend it without a credible paired gain over a comparable current holdout incumbent and independently authenticated organizer-format inputs.

## Verified official context, not empirical proof of a hypothesis

- [DrivenData problem and submission format](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/) describes the 100 m raster, distance-weighted Tversky metric, and outside-bounds handling.
- [DrivenData staff on known-fault masking](https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/4) confirms the scoring mask is pixel-exact and that new labels may occur nearby. Broad collars can therefore suppress valid discoveries.
- [USGS GeoDAWN](https://www.usgs.gov/data/geodawn-airborne-magnetic-and-radiometric-surveys-northwestern-great-basin-nevada-and) describes magnetic and radiometric measurements; magnetic signals, radiometric materials, and subsurface structure are not direct proof of active geothermal venting.
- [USGS geothermal research](https://www.usgs.gov/centers/gmeg/science/geothermal-resource-investigations-project) provides general resource context, not a positive label or a geothermal confirmation for any predicted dot.
