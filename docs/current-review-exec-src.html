How to submit a future candidate — only after every gate turns green

  1. Confirm the method lane first. The current canonical card records lane.assigned: false. Do not infer an assignment from an old artifact, review, or shortlist.
  2. Wait for a fresh run card. It must identify a newly computed raster, evaluator version, withheld-positive count, 95% CI, feature-alone canaries, complete registry scope, both novelty phases, byte hash, and validator output. A historical file or format audit is not a fresh experiment.
  3. Require a strict promotion verdict. The candidate must beat the best comparable HOLDOUT-DTI on the same split/evaluator with paired uncertainty, pass the duplicate rules and leakage canaries, and pass the actual written-byte validator. No score projection qualifies.
  4. Use a separate selector. Only after the card says OK TO SUBMIT: YES should the human selector verify the current weekly allowance and choose one candidate. This review neither selects nor uploads a slot.
  5. Upload the exact named file to DrivenData. Then preserve the submission-page receipt, identifier, timestamp, and score. Only a score copied from that receipt is labeled ORGANIZER-CONFIRMED under this project’s policy.

What the official format and metric say

The official problem asks for faults indicative of geothermal resources, with an initial private expert-labelled fault set and later expert review/expanded labels. It does not provide a geothermal-vent label. The documented prediction file is one float32 GeoTIFF in EPSG:32611 at 100 m, with values in [0,1] and null/NaN outside bounds. The official metric uses a 300 m triangular distance kernel and alpha 0.2 / beta 0.8. This repository’s zero-filled outside-footprint encoding is validated locally; local validation does not guarantee organizer acceptance.

Official links: competition page · problem, metric, and format · rules · public leaderboard · USGS GeoDAWN.

Why a sparse reported result may rise — not causal proof

The official DTI gives each truth pixel its best distance-weighted prediction credit and charges unmatched prediction mass through the false-positive term. Removing low-marginal-utility dots can therefore improve the ratio if coverage credit is retained. But a dot near an already mapped fault is not automatically zero-credit: an unmapped truth pixel may be within the 300 m kernel. A matched, same-fold ablation is needed to prove why a particular file scored as it did.

The user-reported GEMSDOE32 value 0.2778 is not confirmed by a submission-page receipt; its own published page says no organizer score exists. The supplied 0.3195 and 0.4413 are also not receipts for this repository. The current public leaderboard is linked above, but a public listing is not an ORGANIZER-CONFIRMED receipt for GEMSDOE91.
