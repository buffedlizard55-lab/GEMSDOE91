Project-side approval gates before a download link appears

  1. Research preregistration: assign the one permitted method lane; write a mechanism, non-fault mimic, falsifier, layer list, and dose before building.
  2. Input integrity: use the official registered-competitor data or an explicitly authorized mirror; verify hashes, CRS, shape, transform, and vector fault segments.
  3. Leakage: evaluate each feature alone. AUC greater than 0.90 stops the run until explained.
  4. Spatial holdout: use the shared buffered whole-segment hide-and-recover evaluator; derive catalogue-based features from visible segments only; mask visible faults pixel-exactly; calculate pooled DTI with the official 300 m kernel and weights. Record evaluator version, withheld positives, and a segment-level 95% CI.
  5. Novelty: compare the surface before placement and final dots after placement against every registry raster. Correlation above 0.90 or more than 70% of dots within 3 px means duplicate: log it and stop.
  6. Decision: require a result better than the current compliant holdout best. Only a separate selector may promote it to a real weekly slot.
  7. Raster validation: validate the file after writing and reread it. Check one float32 band, exact sample CRS/shape/geotransform, [0,1] prediction values, and the organizer's required null/NaN outside-bounds encoding. Record the raster SHA256.

A preview, build success, or locally inferred score is not a substitute for these gates. The existing local hide-and-recover proxy is not the required evaluator and must not be relabelled HOLDOUT-DTI.
