2 · Exact steps for any future file whose automated submit verdict is YES

  1. Check the machine verdict. Run python generate_submission.py in the repository. It re-reads the TIFF, recomputes its SHA-256, re-checks CRS, shape, transform and range, and prints OK_TO_DOWNLOAD / OK_TO_SUBMIT. Continue only if its OK_TO_SUBMIT field is YES and the separate selector has assigned a weekly slot.
  2. Download the submit-format file. That is the .tif linked on the front page, or its single-TIFF .zip. It is single-band float32, EPSG:32611, 3730×3292, transform (100, 0, 243350, 0, −100, 4508550), with every cell finite in [0, 1] and 0 outside the footprint. This avoids the portal error “Predicted values must be in range [0, 1]”, which came from raw −3.4e38 sentinels and NaN twins. Never upload an audit JSON, a NaN twin or a catalogue file.
  3. Verify the bytes. sha256sum <file>.tif must equal the hash in the run card.
  4. Upload. Use the official submissions page. Paste the recorded name and the note (140 characters or fewer) from the front page.
  5. Record the receipt. Copy the public score from the submission page into the ledger as ORGANIZER-CONFIRMED. Until then, no score exists for the file.

The initial and final rounds use one selected submission. The final round re-scores against labels expanded by expert review of all submissions, over the whole GeoDAWN area (problem description; forum 11550).
