3 · Why 0.2778 is the highest, and can it be beaten? (full derivation: docs/R0_ANALYSIS_S22.md)

  • It is the best-pruned member of one family, proven from bytes. R0 = the 0.2600 raster (D2.8) minus 6,436 dots within 2 px of the catalogue; it contains no pixel that D2.8 does not. GEMSDOE31's 0.2708 file is pixel-identical to GEMSDOE28's, and GEMSDOE36's 0.2750 file is exactly R0 plus 1,200 dots.
  • Why those dots hurt (OFFICIAL): known-fault pixels are masked out and a "new fault" is any fault pixel not already in the catalogue, so a dot 1–2 px beside a mapped trace is an unmatched false positive.
  • One number predicts the next scores (MODEL): assuming the removed or added dots are pure false positives, the first live pair gives T ≈ 5,073; that predicts R0 as 0.2784 (reported 0.2778) and the 1,200-dot GEMSDOE36 file as 0.2742 (reported 0.2750). Those 1,200 dots carry only ≈ 0.013 credit each versus R0's average 0.135.
  • Scale (MODEL, bracketed): about 12,146–13,414 truth pixels in the scored region; R0 recovers roughly 38–42% of them; about nine in ten of its dots are unmatched.
  • Can we beat it? Not uniquely from this sandbox. The fitted live-anchored model puts every independent in-repo raster below R0, the uniqueness rule removes the zones where value concentrates, and the only identified escape is new information (USGS 3DEP 1 m LiDAR; a rank-5 team publicly describes "20 m lidar-derivative U-Net ensembles") — all eight official hosts tested return no connection from here.
