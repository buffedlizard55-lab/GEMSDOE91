### P1 — Registry data manifest overstates local availability

`registry/data_manifest.json` contains `local_present: true` entries and a historical narrative saying data were fetched and verified. The filesystem contradicts that for this checkout because there is no `data/` directory. `registry/preflight.json` is also a dated snapshot (2026-10-28), not evidence of current readiness. The README banner now explicitly warns that the flags are stale here. Use a fresh filesystem-based preflight and refresh the manifest/snapshot only from observed file checks and hashes before any run.

Preserve fail-closed `OK TO SUBMIT: NO`, then reconcile the canonical pointer, page banner and run card in one generated publication step. Do not promote any artifact based on a holdout or projection alone.

### P2 — The requested 9-site numbers are not independently verified here

The README and executive summary include copied site values and detailed historical lineage. The request's score list is user-supplied; this review did not fetch all nine site pages or bind the exact TIF files to organizer receipts. Label those values as user-reported/owner-reported wherever not receipt-backed. Uniqueness cannot be asserted from names, scores or descriptions; it requires raster-level comparison using a defined registry and the requested pre-placement and final-dot checks.

### P2 — Root standing prompt and method-lane assignment need disciplined use

The README does preserve a large standing brief, but it also contains multiple historical appendices and status blocks from prior sessions/branches. The referenced “single method paragraph” is not present as an assignment in the prompt archive; earlier notes also record that gap. The correct safe behavior is no experiment until an explicit lane is preregistered/authorized, rather than selecting or blending concurrent lanes. Keep the 3-experiment/2-hour limit and selector separation.

### P2 — Documentation claims need provenance labels and freshness

Some rendered pages contain precise holdout estimates, projection diagnostics, fleet sizes, novelty percentages, and source-audit claims. They may be valid historical evidence, but the current checkout cannot reproduce them. Each published metric should link to its immutable run card/evaluator version, withheld-positive count, CI, and input hashes; each leaderboard value should link to a dated captured organizer page or receipt. Avoid presenting model projections as leaderboard scores.
