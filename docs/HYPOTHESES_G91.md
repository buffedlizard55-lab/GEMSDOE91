### Conditional scientific explanation — not a verified causal attribution

The organizer defines the task as fault prediction, not direct geothermal-vent classification. The official [metric definition](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/) uses a 300 m triangular distance kernel: for each truth pixel, true-positive credit uses the maximum predicted-probability × kernel contribution; false-positive and false-negative components are distance-weighted, with `alpha=0.2` and `beta=0.8`. A dense/redundant prediction field can therefore pay false-positive cost without increasing TP credit when an additional prediction is not the maximum contributor to any truth pixel. Thinning or deleting predictions can improve the index **if** the removed predictions contributed little unique coverage; it can also hurt if they covered a real new fault. Spacing and pruning are plausible mechanisms, not proof that they caused the reported site value. Local implementations disagree on this aggregation (IR-91-39), so no local metric output is used here.

Historical repository notes characterize the H33-2-B2 parent as a thinning of the H19-5 field under a spacing rule, and document catalogue-distance constraints in later variants (see [`ledger/variant-cards.md`](../ledger/variant-cards.md) and [`IRREGULARITIES.md`](../IRREGULARITIES.md)). Those are repository descriptions, not an organizer receipt or proof that any one edit caused the reported value. The GEMSDOE32 page explicitly disclaims organizer scores. It is therefore not scientifically defensible to assert why a verified score of `0.2778` occurred, or to promise that a new file will exceed it.

## 3. Preregistered validation required before any slot

The top candidate (Rank 1) is **not validated**. If and only if the parallel-run lane is explicitly identified and the shared tools are available, the validation must:

1. Withhold whole fault segments and apply the prescribed spatial buffer; use identical folds for candidate and compliant baseline.
2. Regenerate every catalogue-derived feature from visible faults only inside each fold. Mask visible faults pixel-exactly. No held-out geometry may enter training or feature construction.
3. Test every feature alone first. AUC `>0.90` is a leakage canary and must stop the run until leakage is explained.
4. Score pooled distance-weighted TP/FP/FN under the official DTI (\(\alpha=0.2\), \(\beta=0.8\), 300 m triangular kernel). Do not average fold DTIs in place of pooling components. Record evaluator version, number of withheld positives, and a segment-level 95% confidence interval.
5. Compare the candidate surface against every available registry surface **before** dot placement. After final placement, compare dots against every registry raster. If rank correlation is `>0.90` or more than `70%` of candidate dots fall within 3 pixels of any registry raster's dots, log a duplicate and stop.
6. Promote only if compliant HOLDOUT-DTI beats the current compliant holdout best. A public leaderboard score or a projection is not a substitute. Promotion to a real weekly slot is a separate selector step.
