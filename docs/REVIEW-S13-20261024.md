## 2. The 0.2778 question (answer, with what is verified and what is not)

- **Verified:** the leaderboard page read today shows #1 at **0.4413**, #2 at 0.3916, and #23 at 0.3217 (`https://www.drivendata.org/competitions/306/competition-doe-gems/leaderboard/`). The prompt's "0.3195 is highest" does not match that page.
- **Not verified:** the 0.2778 value for `h33-h33-2-b2…` (GEMSDOE32). The repo's own forensics (`docs/FUSE91_20261024.md` §1, `evidence/forensics_f91_20261024.json`) describe how that file was thinned and pruned. They do not show that its score was organizer-confirmed. Treat 0.2778 as CLAIM.
- **Mechanism from the metric (official page 967,** `https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/`**):** the score is a distance-weighted Tversky index with α = 0.2 and β = 0.8, and missed faults are penalised about four times as heavily as false alarms. So dense, well-spaced dots that cover likely fault traces tend to score well. This explains why such a placement can score high. It does not show how GEMSDOE32 was built.
- **Can we beat 0.2778?** Unknown. No organizer-scored candidate exists in this repo. Our best local measure is a holdout on catalogue recovery, which the repo itself says may not transfer to the expert hidden set (IR-91-S10-04). No holdout number converts to a leaderboard score.
