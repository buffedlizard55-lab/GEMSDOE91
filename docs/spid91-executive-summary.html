Why "Predicted values must be in range [0, 1]" happened — and how we permanently eliminated it

Root Cause 1: In-Footprint Sentinel Bleed (-3.4028235e+38) & Unmasked NaNs

Official training_features.tif carries 3,061 cells inside the active Nevada footprint with float32 sentinel values (-3.4028234663852886e+38), and the official U-Net reference notebook converts < -1e38 to np.nan. Any spatial convolution or unmasked inference leaks NaN or negative values into the output GeoTIFF.

Automated Fix: Every band is scrubbed via isfinite(arr) & (arr > -1e30) and repaired by nearest-neighbor Euclidean distance transform before any FFT or gradient operator runs.

Root Cause 2: Raw Buffer Range Check on nodata=NaN

DrivenData's scorer checks 0.0 ≤ arr ≤ 1.0 across the raster buffer. Writing NaN across the 7,111,787 outside-footprint cells triggers "Predicted values must be in range [0, 1]" whenever NaN is not stripped prior to range checking.

Automated Fix: gems91-spid-e3-20261024T190000Z-25a94861-zeros.tif writes 0.0 outside the footprint with nodata=None and verifies all 12,279,160 float32 cells on disk across 4 independent validator suites (min=0.0, max=1.0, NaN=0, Inf=0).
