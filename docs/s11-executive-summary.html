Why "Predicted values must be in range [0, 1]" happened — and how it is solved

Root Cause 1: Sentinel Bleed (-3.4028235e+38)

In training_features.tif, 3,061 cells inside the Nevada submission footprint carry float32 sentinel values (-3.4028234663852886e+38). Any pipeline that transforms bands without scrubbing sentinels first emits negative values outside [0, 1].

Fix: Every band is scrubbed with isfinite(arr) & (arr > -1e30) and filled via Euclidean distance transform prior to feature extraction, then re-checked before and after writing.

Root Cause 2: nodata=NaN Tag Handling

Some portal validators inspect the raw array buffer before applying the GeoTIFF nodata mask. A file with 7,111,787 outside-footprint NaN cells fails if NaN is tested against 0.0 ≤ x ≤ 1.0.

Fix: gems91-mhtr-e2-20261024T170000Z-9554f718-zeros.tif is written with nodata=None and 0.0 outside the footprint — all 12,279,160 float32 cells are strictly finite and in [0.0, 1.0].
