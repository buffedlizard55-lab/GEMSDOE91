The working decision criterion is **risk-adjusted information per unit cost**, not an imagined leaderboard value. Expected benefit is qualitative and highly uncertain. These are three distinct signal families; none is represented as proven to improve performance or to be globally novel.

## Required validation if a method is later assigned

1. Freeze one assigned method paragraph and a genuinely distinct hypothesis before reading results. This menu does not fill that role.
2. Reuse the repository's pinned feature cache and shared `vendor/gems57` buffered whole-segment evaluator/writer; do not create a private fork. Withhold whole fault segments with a buffer, use catalogue features only from visible faults, mask visible faults pixel-exactly, and score pooled DTI with α=0.2, β=0.8 and the 300 m triangular kernel.
3. Run every feature-alone leakage canary before trusting it; symmetric AUC >0.90 is leakage until resolved. A holdout number must include the evaluator version, withheld-positive count, and 95% CI and be labeled `HOLDOUT-DTI`. A projection is never a score.
4. Run registry surface correlation before placement and final-dot overlap after placement. A failed duplicate check is a negative deliverable; do not continue that candidate or spend a weekly slot.
5. Stop after three experiments or two hours. Selector/promotion remains a separate step, not part of validation.
6. Only a genuinely new, writer-produced TIFF that passes the official sample's CRS, shape, transform, `[0,1]` range, and no-NaN-inside-footprint checks can be labeled `OK TO DOWNLOAD`. Submission needs separate scientific, uniqueness, lane, rights, and selector evidence; a technical pass is not submission approval.
